# Git — почему и примеры

Обоснования к `.claude/rules/common/git.md`. Правило грузится всегда (нет `paths`),
стек-независимо.

## `mv`, не `git mv`

`git mv` неявно стейджит (implicit `git add`), а индекс — за владельцем.

## Readonly-зоны

`READONLY_ZONES` задаётся в `.harness.conf`.

## Инструмент переноса

Слепое копирование «оттуда сюда» молча зашивает допущение, что источник свежее — а когда оно
ложно, работа цели исчезает без ошибки и без следа. Разница в обе стороны — сколько строк есть
только у источника и сколько только у цели. Замер: скрипт подъёма улучшений из инстанса в шаблон
перезаписал бы 20 файлов и снёс 613 строк, существующих только в шаблоне; единственной защитой
был diff на 1300 строк «посмотри глазами» — то есть проверка, которую нельзя пройти внимательно.

## Резолв merge: superset → bulk

Superset видно уже на 2-3 core-файлах. Промах bulk-резолва ловят ярусы 2-3 (типы, тесты). Не
верифицировать каждый файл вручную: стоило ~20 минут на 16 файлах. `--ours` теряет чужое там,
где обе стороны авто-смёрженно добавили своё (пример: `en.json` — feature-ключи `users.sync.*`
нельзя терять при выборе HEAD). Правка конфликт-маркеров редактированием файла — не
git-мутация.
