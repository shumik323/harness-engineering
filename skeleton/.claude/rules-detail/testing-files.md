# Testing при работе с тестами — почему и примеры

Обоснования и замеры к `.claude/rules/common/testing-files.md`. Процедура мутации и разбор
хрупкости — `.claude/docs/testing-guide.md`.

## Мутация связей между слоями

Связь (биндинг родителя на событие ребёнка, проводка хука в компонент) не принадлежит ни одному
участнику, поэтому выпадает из тестов обоих: у ребёнка проверен `emit`, у хука — прямой вызов,
у родителя ребёнок застаблен и события не эмитит. Снос связи оставляет прогон зелёным, а функцию
мёртвой. Наблюдаемое следствие для ассерта — порядок строк, ушедший запрос. Замер: снос одного
биндинга события не уронил ни один из трёх файлов тестов, которые его «покрывали».

## Один вызов в трёх ветках — три мутации

Ветки — create / update / delete, успех / отказ; мутация по одной показательной не годится.
Покрытая ветка маскирует соседние: прогон зелёный, отчёт «связь покрыта» честный по букве и
ложный по сути. Один и тот же вызов стоял в трёх обработчиках успеха, мутация прогнана по
одному — снос из двух других прогон не ронял, дыру нашло ревью. Тот же счёт — к ассертам: для
«сколько раз ушло» нужен счётчик до/после или ассерт на последний вызов.
