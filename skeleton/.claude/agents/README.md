# .claude/agents — роли-агенты (нативный Claude Code)

Субагенты Claude Code: markdown + YAML-фронтматтер (`name`, `description`, `tools`, `model`,
опц. `isolation`). Зовутся через Task tool по имени. Один уровень вложенности (агент не
вызывает агента).

## Что здесь лежит

Только роли, которых нет в плагине. Четыре core-роли (`reviewer`, `scout`, `researcher`,
`scribe`) живут в плагине `md-front-skills/core` и зовутся как `core:reviewer` и т.п. — здесь
их копий нет намеренно (ADR-14: четыре копии одного файла давали четырёхсторонний дрейф).
Плагина в проекте нет — поставь его, иначе этих ролей не будет: `/plugin marketplace add`
на репозиторий `md-front-skills`, затем `/plugin install core@md-front-skills`.

- `Explore.md` — переопределяет ВСТРОЕННЫЙ агент `Explore`, чтобы разведка шла на haiku
  (effort low, read-only по `tools`). Без этого файла поиск по репозиторию идёт по цене модели
  основной сессии.
- `challenger.md` — второй шаг adversarial-ревью: берёт находки первичного ревьюера и проверяет
  их **прогоном**, не рассуждением, плюс добивает пропущенное. Установка скептическая: не удалось
  подтвердить → `REFUTED`, потому что ложная находка дороже пропущенной (тратит время владельца и
  обесценивает остальные). Несёт протокол мутации с обязательным возвратом файла и доказательством
  возврата — оставленная мутация худший исход, следующий агент примет её за код проекта.
  Инструменты записи есть ТОЛЬКО для мутаций, фиксы идут через чекпоинт. Поднят из боевого
  инстанса 14.08, плагинной пары у него нет.
- **Доменное ревью, три роли, работают вместе:** `lens-contracts.md` (данные извне, опциональность,
  потеря данных на пути к пользователю, контракт входного значения) · `lens-tests.md` (критерий без
  теста, ассерт на факт вызова вместо следствия, поведение, от сноса которого не упадёт ни один
  тест) · `arbiter.md` (свод и дедуп; метку `blocks-merge` ставит ТОЛЬКО при наличии `файл:строка`
  и сценария отказа, severity сам не повышает, своих находок не добавляет).
  Линзы идут ПАРАЛЛЕЛЬНО и о находках друг друга не знают — малое пересечение это признак работы,
  а не дефект. Список линз у арбитра не фиксирован: проект добавляет свои, для UI-стека линза
  состояния приезжает с lang-pack. Инструментов записи у всех трёх нет намеренно.
  Для обычной правки это избыточно — хватает `core:reviewer` плюс `challenger`.
- `bug-triage.md` — **scaffold**, обобщён из роли, выросшей в боевом инстансе. Read-only следователь:
  grep gotchas → locate → (diff с reference) → гипотеза → структурный отчёт. **Не редактирует код.**
  При первом использовании в проекте — заполнить плейсхолдеры, навести KB-секцию на реальные пути.

## Какая модель у какой роли

Сверено с `docs/en/sub-agents` и `docs/en/workflows` 23.09. Порядок выбора модели: параметр
вызова → `model` во frontmatter → `CLAUDE_CODE_SUBAGENT_MODEL` → модель сессии. Workflow-агент
без `model` и `agentType` идёт по тому же порядку.

| Класс задачи | Роль | Модель | Почему |
|---|---|---|---|
| Поиск файлов, разведка | `Explore`, `core:scout` | haiku, effort low | механика, результат перепроверяется |
| Текст по готовому плану, ресёрч | `core:scribe`, `core:researcher` | sonnet | связный текст, решений не принимает |
| Триаж бага | `bug-triage` | sonnet | read-only следствие по шаблону |
| Ревью, проверка находок | `core:reviewer`, `challenger` | inherit | ценность в силе модели; дешевле — `REVIEW_MODEL` оркестратора |
| Доменное ревью | `lens-*`, `arbiter` | opus | осознанный пин; менять только по замеру |
| Без пина: `general-purpose`, стадии workflow | — | `CLAUDE_CODE_SUBAGENT_MODEL` | пол; судья и синтез в workflow — `model: 'opus'` явно |

Грабли:
- Поле `model` опущено — это `inherit`. На Opus-сессии роль без пина стоит как Opus.
- Плагин не переопределяет встроенного агента: `core:Explore` станет вторым агентом рядом.
  Переопределить можно только файлом в `.claude/agents/` или `~/.claude/agents/`.
- До v2.1.251 `CLAUDE_CODE_SUBAGENT_MODEL` перебивал frontmatter. Сейчас стоит ниже.

Проверка — `model-usage.sh --days N` из `md-front-skills/scripts/`: какие модели реально
ответили ролям, по транскриптам.

## Слой и синк

Агенты — **instance-owned scaffold**, не CORE. Каждый проект кастомизирует роль под свой
стек и базу знаний (боевой инстанс это доказал: свои пути, свой файл learnings, специфика
валидатора форм). Поэтому
`.claude/agents` исключён из Copier-синка (`copier.yml` → `_exclude`), как и `.claude/docs`:
обновления метода НЕ форсятся сверху.

**Доставка — reference-by-copy, не авто.** Раз `agents/` исключён из copier, `copier copy/update`
его в инстанс НЕ кладёт. Это эталон: когда инстансу нужна роль — скопировать файл руками в свой
`.claude/agents/`, заполнить плейсхолдеры, дальше владеть им сам. Авто-доставки при init нет
(в отличие от CORE) — это осознанно: пустой агент-плейсхолдер в каждом репо вреднее, чем явное
принятие роли по нужде.

## Как завести новую роль

1. Скопировать `bug-triage.md` как образец структуры (фронтматтер + метод + guardrails + output).
2. Сузить `tools` до минимума роли. Read-only роль → без `Write`/`Edit`; следящая роль → без
   side-effect Bash (`npm run`, тест-раннеры).
3. Прописать guardrails явно: что агент НЕ делает. Read-only роль обязана останавливаться на
   описании правки, не на её внесении.
4. Output format — жёсткий шаблон, чтобы оркестратор парсил ответ предсказуемо.

## Сверено с доками Claude Code

Источник: https://code.claude.com/docs/en/sub-agents.md. Что важно знать, чтобы не дорабатывать:

- **`tools` — это enforcement, инструкция в промпте — нет.** Отсутствие `Write`/`Edit` в allowlist
  реально блокирует правки. А вот «Bash только для git» промптом НЕ форсится: если `Bash` в списке,
  агент может запустить что угодно. Жёсткая гарантия = убрать `Bash` или `permissionMode: auto`
  (classifier вет ит команды).
- **`description` = триггер автоделегации**, не «что делает». `bug-triage` намеренно БЕЗ
  «Use proactively» — триаж зовут явно, а не на каждое упоминание ошибки. Хочешь автозапуск роли —
  добавь «Use proactively when…».
- **`model: inherit`** по умолчанию (если поле опущено). Явный `sonnet`/`haiku`/`opus` —
  осознанный выбор стоимости/мощности.
- **`memory: project`** — опция для роли, которая копит знание между сессиями (например, триаж копит
  классы багов). Пишет в `.claude/agent-memory/<name>/`, шарится через git. Не включена в scaffold —
  добавь, если роль должна учиться.
- **Загрузка при старте сессии.** Правка `.md` напрямую не подхватывается на лету — рестарт сессии
  или интерфейс `/agents` (применяет сразу).
- **Plugin-агенты теряют** `hooks`/`mcpServers`/`permissionMode`. Эти агенты — проектные
  (`.claude/agents/`), не plugin, поэтому поля работают.

## Чего здесь намеренно НЕТ

Роли `verifier` / `bugfixer` / оркестратор — **по реальной боли, не впрок** (`rules/common/workflow.md`:
build from failures). Под них пока нет боевого артефакта, который стоит обобщать. `bug-triage` есть —
поэтому он здесь. Появится повторяющаяся нужда в проверяющем/фиксящем агенте — заводить по этому же
образцу.
