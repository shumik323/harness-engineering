# feature

Трек A из `rules/common/methodology-routing.md`, собранный в один запуск. Скил ничего не
дублирует: каждый шаг отсылает к документу, где лежит содержание.

Первой строкой хода скажи вслух: «Трек A: <что строим>». Не уверен, что это A, а не B/C, — спроси
одной строкой, не угадывай.

## Состояние — в файле плана, не в чате

Один файл плана на фичу (каталог — как принято в проекте, нет такого — `docs/plans/`). В нём
чекбоксы шагов из списка ниже. Чат после `/compact` ничего не помнит, файл помнит.

**При входе** найди файл плана этой фичи (по тикету или имени). Нашёл — прочитай, продолжай с
первого незакрытого `- [ ]`, назови его вслух. Нет — создай с шагами ниже и иди с шага 1.
Шаг отмечай `- [x]` сразу после «да» владельца или прогона проверки, не пачкой в конце.

## Шаги

- [ ] **1. Разведка.** Что уже есть в коде, прецеденты, затронутые слои. Механика поиска — агенту
      `scout`. Результат — абзац в секции Context плана, с `файл:строка`.
- [ ] **2. Прожарка.** Скил `core:grilling` по развилкам фичи. **СТОП: жди «да» владельца.**
      Решения прожарки идут в «Допущения и развилки» плана.
- [ ] **3. План.** Скил `/plan`: все обязательные секции заполнены или явно «нет». **СТОП: жди «да».**
- [ ] **4. DoR-гейт.** Чеклист и процедура — `.claude/docs/dor-gate.md`. Каждый пункт: получено /
      отсутствует / не применимо. Есть «отсутствует» — срез не берём, решает владелец.
      **СТОП: жди «да».**
- [ ] **5. Слои.** Реализация по плану, слой за слоем. После каждого слоя — его проверка из
      Verification плана; на границе слоя предложи `/compact` (состояние уже в файле).
- [ ] **6. Независимый ревью.** Один свежий ревью-агент (`core:reviewer`), чеклист —
      `.claude/docs/REVIEW.md`. Находки: однострочный фикс — сразу, иначе список и план, ждёшь «да».
- [ ] **7. Completion.** Онбординг, «как проверить руками», comprehension-gate — по
      `.claude/docs/completion.md`. Закрыто, когда владелец подтвердил понимание, не раньше.

## Правила хода

- **Три остановки (2, 3, 4) — жёсткие.** Молчание и «звучит нормально» не «да». Не получил «да» —
  следующий шаг не начинаешь.
- **Пропуск шага — только с озвученной причиной** и пометкой в плане («шаг 2 пропущен: <почему>»).
  Тихий пропуск — нарушение.
- **Новая развилка посреди слоёв** — стоп и вопрос владельцу, в план не зашивай молча.
- **Статус «готово» — после прогона проверки**, не по ощущению. Boundary-фича — строка
  `verified: real-runtime` или честный `verified: tests-only` (`rules/common/testing.md`).
- **Коммит — только по явному слову владельца.**
