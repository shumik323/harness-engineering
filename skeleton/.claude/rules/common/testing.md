# Testing — verify-before-ship

- **Ярус 0 (pre-commit, линтер staged) шаблон не ставит** — заводит проект; тяжёлое туда не вешать.
- **Sensor (PostToolUse)** гоняет тесты при правке в `WATCH_DIR`; ручным прогоном не дублируй.
- **Gate (Stop, Ярус 2)** — `GATE_CMD` (type-check + lint + build), без полных тестов; exit 2 → ход не закрыть.
- **Pre-push (Ярус 3)** = gate + секрет-скан + сверка AC ↔ тест + полные тесты + покрытие изменённых строк, в этом порядке (`.claude/guards/pre-push.sh`).
- **`check-ac-refs.sh`:** каждый AC-ID спеки — со ссылкой из теста; Stop предупреждает, push блокирует. Порог только вниз, поднять — отдельным коммитом с причиной.
- **Покрытие — по изменённым строкам** (`COVERAGE_REPORT`), не по проекту.
- **Секрет-скан (`SECRET_SCAN_CMD`) — на push.** Ключ ушёл в push → ротация, даже если коммит удалён.
- **`HARNESS WARNING` от gate — дрейф среды:** выровняй её или скажи вслух, что verify шёл на дрейфе.
- **Дыра sensor'а:** массовый `lint:fix`/`format` через Bash PostToolUse не дёргает → прогони тесты вручную.
- **Тест = критерий готовности:** не зелёный — не закрыто. Осознанно меняешь поведение → обнови ожидания теста/снапшота, не подгоняй тест под баг.
- **Упал тест компонента вне текущей фичи → СТОП:** причина + варианты пользователю, чужой тест/компонент не править. Исключение — явное согласие.
- **Ложный красный лечи сужением правила, не флагом-обходом.** Новое правило сначала прогони по своему коду.
- **Нет данных → не создавай носитель** (файл-пустышку, всегда-нулевую колонку) и скажи строкой почему.
- **Проверочный артефакт не теряет входы молча:** необработанное — секцией или падением; счётчик — по напечатанному.
- **Автоматика — компактный reporter и тихий `stderr`;** подробности — прогоном по файлу.
- **Не можешь проверить автоматически → проверь руками** и скажи явно; непроверенное за готовое не выдавай.
- **Среда «недоступна» — только после попытки открыть её путём пользователя;** косвенные признаки не доказывают.
- **Проверяй в состоянии реального использования:** tagged ref, прод-конфиг, чистая установка.
- **Boundary-фича (сеть/API/env/внешний сервис) → перед «готово» строка** `verified: real-runtime` ИЛИ честный `verified: tests-only`. UI-инструмент — `rules/lang/<lang>.md`.
- **Real-runtime на чужих данных:** пустое поле — сначала живость ссылки в данных; контроль — на сущности, созданной в сценарии.

Пишу или ревьюю тест (и через diff) — сначала Read `testing-files.md`.
Почему и примеры: `.claude/rules-detail/testing.md`
