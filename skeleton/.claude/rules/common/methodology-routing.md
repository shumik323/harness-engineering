# Methodology Routing — харнесс по умолчанию

## Класс задачи → трек (вслух первой строкой хода: «Трек B: баг в списке Teams»)

- **A — фича / новый срез / boundary.** Вход — `/feature`. Разведка → grilling (`core:grilling`) → `/plan` → DoR (`.claude/docs/dor-gate.md`) → слои → независимый ревью → completion (`.claude/docs/completion.md`). Пропуск ступени — с озвученной причиной.
- **B — баг / регрессия.** Репро ДО гипотезы, минимальный кейс, фикс, тест, который без фикса падал бы. Дизайна и DoR нет. «Похоже на X» — не диагноз. `superpowers:systematic-debugging` — по явному запросу.
- **C — мелкая правка / диагностика / чужой MR / тексты.** Сразу работа + verify, без плана, гейтов и ревью-агента.

Трек — по природе, не размеру: правка контракта на две строки — A. Сомнение между соседними — старший, вслух.

- **В рабочих проектах (этот репо и инстансы) — только этот харнесс.** Стороннее (superpowers и др.) — по явному запросу: пользователь назвал инструмент/метод («через brainstorming», «по TDD»).
- **Запуск стороннего — вслух:** «внешний плагин X, делает Y».
- **Чекпоинт бьёт continuous:** на необратимом (установка, чужой репо, удаление) — стоп и вопрос, даже если скил велит не тормозить.
- **Сторонний скил — исполнитель, SDD-контракт (критерии готовности) — свой.** Методологию и superpowers в репо не копировать.
- **Вне рабочих проектов** (эксперименты, личное, вики) — стороннее ок как дефолт.
